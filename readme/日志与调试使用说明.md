# gEmuera 日志与调试系统使用说明

> 面向使用者（玩家 / 测试 / 开发者）的实操手册。系统本身在 `Scripts/Diagnostics/`，
> 配置在 `config.toml`，本文件只讲"怎么用"。

---

## 1. 这是什么

gEmuera 的日志/诊断系统是**结构化 + 限流 + 脱敏**的三层管线：

```
业务代码 (GenericUtils.Info/Warn/Debug, ImageTrace ...)
   │  路由前先查开关（等级/类别/模块子开关，缓存为位掩码，零分配）
   ▼
DiagnosticLogRouter（限流：帧/秒/事件桶；脱敏：路径/文本截断）
   ▼
DiagnosticLogSinks
   ├── 内存 ring buffer（最近 N 条，面板实时查看）
   ├── 持续文件 sink（user://gemuera_runtime_<时间戳>.log，1 MiB 轮转）
   └── Godot 控制台镜像（≥Error 恒开，其余可开）
```

**生产级能力清单**（审计结论，2026-08）：

| 能力 | 状态 |
|---|---|
| 结构化事件（eventId + category + data） | ✅ |
| 等级/类别/模块子开关（含位掩码缓存） | ✅ |
| 限流（每帧 / 每秒 / 每事件桶 + 丢弃统计） | ✅ |
| 脱敏（路径归一化、文本截断、换行替换） | ✅ |
| 环形缓冲（容量可配，含覆盖计数） | ✅ |
| 文件 sink（1 MiB 轮转、路径越界校验、开失败自动降级、worker 线程安全） | ✅ |
| config.toml 热重载（保存即生效） | ✅ |
| 会话关联（session_id、monotonic 时钟） | ✅ |
| 诊断包导出 + 留存清理 | ✅ |
| 输入回放 / 快照 / 面包屑 | ✅ |

**主要缺口**：文档缺失（本文件补齐）、部分 verbose 日志在 Release 构建被 `[Conditional]` 编译掉（见 §8）。

## 2. 快速开始（三步）

1. **确认配置**：`config.toml`（`user://` 或游戏目录 `res://`，优先级 user > res）。
   默认 `logging.enabled = true`、`level = "warn"`、`file_sink = false`。
2. **开启持续文件日志**（排查问题必备）：
   ```toml
   [logging]
   enabled = true
   level = "info"        # 或 debug / trace
   file_sink = true      # 写入 user://gemuera_runtime_*.log
   ```
3. **看日志**：
   - 游戏内：右上角诊断悬浮球 → 「日志查看」实时看 ring buffer。
   - 文件：`user://gemuera_runtime_<yyyyMMdd-HHmmss>.log`。
   - 保存/导出：面板「导出诊断包」按钮。

---

## 3. config.toml 关键键速查

| 段 | 键 | 说明 | 默认 |
|---|---|---|---|
| `[logging]` | `enabled` | 总开关（false 时连错误也不记录） | `true` |
| `[logging]` | `level` | 全局最低等级 `error|warn|info|debug|trace|none` | `warn` |
| `[logging]` | `file_sink` | 持续文件日志开关（受 enabled 双重门控） | `false` |
| `[logging]` | `file_sink_level` | 文件写入最低等级（独立于全局） | `info` |
| `[logging]` | `panel_visible` | 启动挂载诊断悬浮球（等价 `debug.runtime_panel.enabled`） | `true` |
| `[logging]` | `mirror_non_error_to_godot` | 把非 Error 日志镜像到 Godot 控制台 | `false` |
| `[logging]` | `diagnostic_ring_capacity` | ring buffer 条数 | 按代码 |
| `[logging.categories]` | `sprite/input/script/...` | 按类别过滤 | — |
| `[logging.rate_limit]` | `enabled` / `default_per_second` / `per_event_per_second` | 限流 | — |
| `[logging.redaction]` | `enabled` / `max_path_chars` / `hash_sensitive_text` | 脱敏 | — |
| `[quick_debug]` | `enabled` / `preset` / `language` | 一键调试预设（见 §4） | `normal` |
| `[debug.runtime_panel]` | `enabled` / `allow_runtime_toggle` / `persist_changes` | 面板行为 | — |
| `[diagnostic_package]` | `enabled` / `include_log` / `include_device_info` ... | 诊断包内容 | — |

> 配置里已有的中文注释是权威说明；本表是速查，冲突以 `config.toml` 内注释为准。

## 4. quick_debug 预设（一键开关）

`[quick_debug] preset` 可选：

| preset | 适用场景 |
|---|---|
| `normal` | 默认，什么都不额外开 |
| `touch_input` | 排查触摸/输入（指针、拖拽、捏合、惯性、滚动） |
| `image_ui` | 排查图片/UI 布局（resolve、texture、render_rect、cache、color_matrix） |
| `resource_storage` | 排查资源/存储（sprite、audio、sqlite、Android 外部存储路径） |
| `performance` | 性能采样（FPS、帧耗时、UI 队列、纹理队列、内存） |
| `apk_issue` | APK 常见问题组合（推荐真机排查时用） |
| `custom` | 只信 `quick_debug.modules` 里显式开的模块 |

语言 `[quick_debug] language = zh_cn | jp | en`，展开对应 `debug_model_*`。

## 5. 运行时诊断面板

- **打开**：默认启动挂载右上角悬浮球；点开即面板。`config.toml` 的 `panel_visible = false`
  可关闭启动挂载；运行时也可用 `GenericUtils.SetDiagnosticsPanelVisible(true/false)`。
- **主要功能**：日志查看（ring buffer 实时）、开关热重载（保存写 `user://config.toml`）、
  模块细分开关、导出诊断包、留存清理、输入回放。
- **热重载**：面板改动写 `user://config.toml` 后轻量开关立即生效，结构性参数重启生效。

---

## 6. DEBUG 模式与调试窗口

- **开启 DEBUG 模式**：启动参数/配置进入 `Program.DebugMode`。
- **调试窗口**：DEBUG 模式下启动且 `Config.DebugShowWindow` 时自动打开「调试窗口 (Debug)」，
  也可在调试控制台执行 `DEBUG` 命令打开。
- **窗口形态**：自 2026-08 起从"画布内嵌面板"重构为 **Godot 原生 `Window`**——
  - 桌面端：按项目 `embed_subwindows` 设置可为**独立 OS 窗口**，不再遮挡游戏画面；
  - Android：**带标题栏、可拖动/缩放的浮动子窗口**，仍悬浮于游戏之上但可移开。
- **三个 Tab**：
  - **变量监视**：添加表达式（如 `DAY`、`CFLAG:100`），worker 侧求值实时回显；
  - **调用栈**：当前执行文件/行号 + 调用栈；
  - **调试控制台**：执行调试命令（`SET DAY:0`、`PRINT 文本` 等）。
- **关闭**：标题栏 ✕ 或面板内 ✕ → worker 侧保存 `console.log` + `watchlist.csv` 到 `debug/`。

> 引擎在 worker 线程、窗口在 Godot 主线程，跨线程数据走快照队列（只读 DTO），
> 主线程绝不直接读引擎缓冲——避免线程竞争。

## 7. 日志文件都在哪

| 文件 | 路径 | 内容 |
|---|---|---|
| 持续日志 | `user://gemuera_runtime_<时间戳>.log` | 通过路由的 Info/Error 等（`file_sink=true` 时） |
| 启动加载计时 | `<游戏目录>/debug/load_times.log` | `preload/resources/gamebase/csv/erh/erb/total` 各阶段毫秒数（**始终落盘**，Release APK 也有效） |
| 调试窗口控制台 | `<游戏目录>/debug/console.log` | DEBUG 模式调试控制台输出 |
| watch 列表 | `<游戏目录>/debug/watchlist.csv` | 调试窗口变量监视列表 |
| 导出诊断包 | 面板导出，写入 `user://` 或配置目录 | 日志 + 配置快照 + 设备/Godot/APK 信息 |

## 8. Release / APK 构建注意事项

- `GenericUtils.Info/Warn/Debug` 等标注了 `[Conditional("DEBUG")]` /
  `[Conditional("GEMUERA_DIAGNOSTIC_LOGS")]`：**Release 构建默认被编译掉**，
  只保留 Error 级与结构化日志。需要完整诊断的 APK，请在 csproj 加：
  ```xml
  <DefineConstants>GEMUERA_DIAGNOSTIC_LOGS</DefineConstants>
  ```
- 发布给测试的 APK，建议同时：`file_sink=true`、`level=debug`、面板开，
  这样反馈时直接要 `gemuera_runtime_*.log` + 诊断包，少来回问。

## 9. 常见问题排查

| 症状 | 排查 |
|---|---|
| 看不到任何日志 | ① `logging.enabled=true`；② 等级太高（`warn` 会滤掉 info）；③ 检查是不是 Release 构建把 verbose 编译掉了（§8） |
| 日志文件不生成 | `file_sink=true` 且 `logging.enabled=true`；文件在 `user://` |
| DEBUG 看不到游戏内容 | 已修复：调试窗口改为独立 Window，可拖动/缩放移开，不再覆盖画面 |
| 卡顿怀疑日志刷屏 | 检查限流丢弃统计（面板），把对应类别/模块子开关关掉 |
| 需要反馈给开发者 | 导出诊断包 + `load_times.log`，附设备型号与 Godot 版本 |

## 10. 架构注释（给开发者）

分层：`GenericUtils`（入口，延迟构造 message）→ `DiagnosticLogRouter`（路由/限流/脱敏，
热路径位掩码缓存）→ `DiagnosticLogSinks`（ring buffer / 文件 / 控制台）。配置装载
`RuntimeDiagnosticsConfigLoader` 支持 `user:// → res:// → BaseDir → CWD` 优先级与 quick_debug
预设展开。详细设计见各文件头注释。
